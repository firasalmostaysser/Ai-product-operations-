# Portfolio Projects

## Your Portfolio Strategy

Every project you build should:
1. **Solve a real problem** — not just "hello world" demos
2. **Be documented** — README with problem, solution, tech stack, how to run
3. **Be on GitHub** — publicly visible
4. **Have a demo** — screenshot, video, or live link
5. **Tell a story** — what was the before state, what did you build, what changed?

## What Recruiters and Clients Look For

When a recruiter or potential client reviews your GitHub, they're checking:
- "Can this person actually build things?" → Yes if you have 5+ working repos
- "Do they understand AI?" → Yes if you have agents, RAG, or tool calling
- "Are they organized?" → Yes if your READMEs are clear and professional
- "Are they prolific?" → Yes if you have consistent commit history

**Minimum viable portfolio for job applications:** Projects #1–5 (can be done in 3 weeks)
**Minimum viable portfolio for freelancing:** Projects #1–6 + one real client testimonial
